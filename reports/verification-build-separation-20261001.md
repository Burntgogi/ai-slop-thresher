# 재검증·재빌드 분리 검토와 구현

2026-10-01. 이번 범위는 정보 없는 반응의 제거와 재검증·재빌드 혼재 두 항목이다. 호출 구조 변경, 비교 UI 보강, 사람 평가 공개 갱신과 VM 추가 시험은 포함하지 않는다. 아래는 최초 검토와 그에 따른 v1.2.1 후보 구현 기록이다.

## 구현 상태

`verify_release.py`는 기록된 체크섬과 ZIP을 읽고, `--source`를 지정한 경우에만 현재 원본과도 비교한다. 사례 검사와 A/B 집계는 기본 실행에서 파일을 쓰지 않으며, 결과를 저장하려면 `--apply --output <새 폴더>`를 지정한다. 전체 후보 패키징도 기본 실행은 계획만 출력하고, 실제 생성에는 소스 밖의 새 출력 폴더를 요구한다. 기존 출력 폴더를 덮어쓰지 않는다.

재빌드에 포함할 파일은 Git 추적 파일과 `--include`로 지정한 파일로 제한한다. 작업 자료 ZIP에는 포함 목록을 기록해 Git 없이도 재빌드할 수 있도록 했다. 협업 도구 코드와 세션 원응답은 탈곡기의 빌드 범위 밖에 둔다. 원본의 플러그인 생성물을 갱신하는 별도 `distribute.py build --apply`와 후보 ZIP 생성을 문서에서 구분했다.

자동 검사는 읽기 전용 실행 전후의 저장소 파일 보존, 새 출력 폴더만 쓰는 빌드, 손상된 ZIP의 거부와 기존 릴리즈 무결성·현재 소스 일치의 분리를 확인한다. 검증 과정에서 출력 변수 충돌로 임시 검사 폴더가 생성되어 수정하고 해당 폴더를 제거했다. 재발을 잡도록 사례 검사·A/B 집계 전후의 비교 범위를 저장소 전체로 넓혔다. 실행 결과와 릴리즈 준비 판단은 후속 준비 보고서에 기록한다.

## 최초 검토

현재 `evaluation/package_artifacts.py`는 플러그인 생성물, 배포 ZIP, 현재 검증 JSON과 SHA256SUMS를 쓴다. `evaluation/run_checks.py`도 저장된 사례를 검사한 뒤 `evaluation/checks/`의 JSON을 다시 쓴다. `evaluation/ab-20260930/aggregate.py`는 기존 판정을 재집계하면서 요약·매핑 해제 결과·무결성 목록을 다시 쓴다. 따라서 검증과 쓰기 작업의 혼재는 ZIP 생성기에만 한정되지 않는다. 반면 개선 기록의 `record.py verify`와 `scripts/distribute.py check`는 결과를 출력하며 자료를 갱신하지 않는다.

권장은 기존 계산을 재사용하면서 **검사와 저장을 명시적으로 분리하는 것**이다. 새 파이프라인이나 배포 서비스를 만들 필요는 없다.

| 작업 | 동작 | 권장 명령 형태 |
| --- | --- | --- |
| 기존 릴리즈 검사 | ZIP·멤버·기록된 체크섬을 읽어 대조하고 성공/실패를 출력한다. 파일을 쓰지 않는다. | `python -B scripts/verify_release.py --artifacts <릴리즈 폴더>` |
| 현재 후보 검사 | 공통 지침·생성물 일치, 상대 참조, 기존 사례와 판정 기록을 대조한다. 자료를 덮어쓰지 않는다. | `python -B scripts/distribute.py check`, 기존 평가기의 읽기 전용 검사 모드 |
| 후보 재빌드 | 현재 작업 원본으로 명시한 새 출력 폴더에 ZIP·검증 기록·체크섬을 만든다. 설치하지 않는다. | `python -B evaluation/package_artifacts.py --output <새 폴더> --apply` |

기존 릴리즈의 무결성과 현재 소스와의 일치는 별도 판정이어야 한다. 소스가 미공개 후보로 바뀌어도 이전 ZIP이 기록된 체크섬과 일치하면 기존 릴리즈 검사는 통과할 수 있다. 이전 ZIP을 현재 후보와 다르다는 이유로 훼손됐다고 보고하거나, 현재 후보와 같게 하려고 ZIP을 다시 쓰지 않는다.

재빌드는 출력 폴더를 필수로 받고 기존 ZIP·체크섬이 있는 폴더를 거부하는 편이 단순하다. 기본 실행은 생성 계획만 보여 주며 `--apply`에서만 쓴다. 플러그인 생성물과 검증 JSON도 출력 폴더 안에서 만들도록 해 소스의 `plugins/`·`research/`·`dist/`를 부수적으로 갱신하지 않는다. 과거 입력·출력·판정 파일은 재빌드에서도 쓰지 않는다. 현재 스냅샷의 전체 작업 자료를 만들면 미커밋 파일이 포함될 수 있으므로 빌드 대상은 명시한 소스와 포함 목록으로 정한다.

기존 패키징 진입점에는 인자 없는 쓰기 실행을 막는 안내를 두고, `docs/verification.md`의 재검증 명령에서 생성 명령을 분리한다. 사례 검사·A/B 집계도 계산 결과를 반환하는 함수와 저장 함수를 나누고, 쓰기는 `--apply` 같은 명시적 선택에서만 수행한다. 기존 JSON과 판정은 읽기 전용 모드에서 그대로 보존한다.

이 변경을 구현할 때 필요한 검증은 세 가지다. 읽기 전용 검사 전후의 입력·기록·ZIP 해시가 같아야 한다. ZIP이나 보호된 기록을 바꾼 대조군은 실패해야 한다. 재빌드는 새 출력 폴더만 쓰고 기존 릴리즈 및 소스 트리를 바꾸지 않아야 한다. 새 의미 평가나 광범위한 하네스 시험은 이 검증의 범위가 아니다.

첫 항목의 미공개 지침에서는 내용 없는 흥미·칭찬과 필요한 평가를 구별했다. N16의 반복 흥미 표현은 이번 사용자 기준에서 삭제 대상이다. 원래 A/B의 판정자 이견과 통과 집계는 당시 기록으로 유지한다. 출력에서 평가를 덜었다는 관측과 당시 기준의 의미 실패 판정도 덮어쓰지 않는다. 사용자 설치본과 공개 배포물은 다음 버전 배포를 요청받기 전까지 유지한다.
