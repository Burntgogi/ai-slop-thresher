# AI Slop 탈곡기 1.2.0 후보 개선 핵심 보고서

2026년 9월 30일. 상태: 다섯 차례 개선·삼자 감수와 감수 교정 완료, 미커밋·미공개 후보로 사용자 검토 대기.

공통 윤문 스킬과 Codex 플러그인 배포를 분리했다. `skills/`에는 하네스 중립 지침을 두고, `integrations/codex/`의 메타데이터를 합쳐 Codex 플러그인을 생성한다. Codex·Claude Code·OpenCode·Cursor·직접 지정 경로로 설치할 수 있으며, Codex 설치에만 `agents/openai.yaml`을 넣는다. 설치 기본값은 미리보기이고 기존 스킬을 덮어쓰지 않는다. [설치 안내](../docs/installation.md)

앞 문장을 부정한 뒤 같은 내용을 다시 정의하는 반복 수사는 줄이되, 실제 정정·책임·피해·원인 구별·위험·조건·유보는 보존하도록 했다. 원문에 없는 안심이나 긍정적 재해석을 붙이지 않는다. 원문 저자의 평가를 임의로 뒤집지도 않는다. 의미가 모호하면 유지한다. [공통 지침](../skills/ai-slop-thresher/SKILL.md)

## 삼자 감수와 교정

R1 감수에서 실제 Dot이 빌드의 복구 결함을 발견했다. 새 출력 배치와 이전 백업 복원이 모두 실패하면 `finally`가 유일한 백업까지 삭제했다. 별도 Codex 감사자도 이를 재현했다. 교정 후 같은 실패를 주입하면 원본 바이트를 가진 백업을 보존하고 경로를 알리며, 미해결 백업이 있으면 재빌드를 중단한다. 이 교정은 완료된 다섯 회차 뒤의 감수 교정으로 구별한다. [전후 증거](../evaluation/improvement-20260930/post-review-recovery.json)

현재 R3 후보 식별자는 `b65968890cd7abfd03872b78b89765892727d0bd478d7ae5c19e49cc10d3de2c`다. 구현·사용 문서·선택한 평가 증거 51개 파일을 해시로 고정했다. R2 대비 설치 문서 한 파일만 바뀌었다. Dot의 Linux 실행에서 같은 member 바이트라도 OS별 `ZipInfo.create_system` 때문에 ZIP 해시가 달라지는 것을 확인해, 재현성 안내를 같은 OS·Python·압축 라이브러리 환경으로 한정했다. 감수 응답과 이 보고서는 이후 추가하며 전체 자료 ZIP만 다시 포장한다. [감수 manifest](../evaluation/improvement-20260930/review-manifest.json)

| 감수자 | 최종 검토 상태 |
| --- | --- |
| Codex | R3의 51개 파일과 패킷을 독립 검증하고 감수 통과. R2의 Windows 실행 검사와 R3의 문서·메타데이터 검사를 구분. [감수 기록](codex-review-20260930.md) |
| Dot HMX-13 | R2의 51개 실제 파일·해시와 Linux 실행 검사 완료. 복구 결함 수정 확인, ZIP 재현성 한계 발견. R3 전체 해시 재검증은 받지 않았으며 해당 문서 교정은 Codex가 검증. [실제 응답](dot-review-20260930.md) |
| Muse | R3 핵심 10개 파일의 정적 감수 통과. 최종 출력 16건과 경계 2건을 대조해 필수 수정 결함을 발견하지 못했다고 판단. 전체 51개 해시 검사·테스트 실행은 하지 않았으며 나머지 범위는 Codex 검증으로 보완. [실제 응답](muse-review-20260930.md) · [화면 증거](muse-review-20260930.png) |

긴 메시지의 HTML 변형과 파일 추출 제약은 사용자 계정의 [비공개 감수 페이지](https://chatgpt.com/space/page_3b2ed8a81b68819195557b40c1bc5612)에 원본 파일을 첨부해 해결했다. 공유 정책은 바꾸지 않았다. R3 첨부 245,337바이트의 SHA-256은 `991cfe786d65683a3b195d376aadc4d86e58a632dd39abb4d645de158d4fa5bf`다. Dot 파일 전달과 Linux 검증은 사용자 PC의 Chrome 없이 완료했다. 최종 Muse 전달에서 Dot 부모 작업이 멈춰, Codex가 사용자 PC의 Chrome에 열린 Muse로 핵심 파일을 전달했다. 따라서 이번 최종 감수 전체를 PC Chrome 없이 완료했다고 주장하지 않는다.

Muse가 남긴 선택적 개선 의견은 빌드 교체 실패 후 기존 파일 복원이 성공했을 때도 오류에 복원 성공을 표시하는 것이다. 현재 코드의 백업 보존·복원 검사에는 실패가 없고, 필수 수정 요구도 아니어서 이번 동결 후보에 추가하지 않았다. 삼자 감수는 서로 다른 제품·실행 환경의 검토이며 독립 인간 평가나 서로 다른 기반 모델의 품질 검증을 뜻하지 않는다.

## 검증과 보류 상태

Windows Python 3.13.5에서 전체 테스트 34개 중 31개 통과, 3개는 심볼릭 링크 생성 권한 때문에 건너뛰었다. 실제 Windows junction·기존 스킬 충돌·버전 불일치·복구 실패 주입은 통과했다. 두 스킬은 `skill-creator` 형식 검사에 통과했고, 다섯 회차 해시·누락 검사, 과거 fixture 검사와 오류 대조군 4개, `python -O` 패키징, 소스/ZIP 바이트 대조, `git diff --check`를 확인했다. [검증 기록](../evaluation/improvement-20260930/validation.json)

Dot의 Python 3.12.14·Linux 감수에서는 distribution 테스트 33개 중 32개 통과, Windows junction 한 건은 건너뛰었다. Windows에서 못 실행한 symlink 세 건은 Linux에서 통과했다. Dot은 역사 자료가 빠진 선택 패킷을 받았으므로 legacy 전체 테스트와 82개 기록의 완결 검사를 실행하지 않았다. 두 환경의 테스트 수를 합산해 별도 성공률로 표현하지 않는다. [Dot 실행 출력](../evaluation/improvement-20260930/dot-execution-evidence.json)

배포물은 [portable 스킬 ZIP](../dist/ai-slop-thresher-portable.zip), [Codex 플러그인 ZIP](../dist/ai-slop-thresher-codex-plugin.zip), [전체 작업 자료 ZIP](../dist/ai-slop-thresher-workbench.zip)이다. portable과 플러그인은 법적 고지와 상대 참조를 포함한다. 실제 하네스 UI 설치·자동 선택·다른 모델의 윤문·VM 간 스킬 자동 동기화는 검증하지 않았다.

기준 커밋 `1ce5dddaff01c4353a71bbaf2abcb03f66dd4965`에서 작업했으며 커밋·푸시·릴리즈·실제 사용자 스킬 설치는 수행하지 않았다. 사용자 검토를 위해 대기한다.

## 릴리즈 후속 기록

위 내용은 릴리즈 요청 전 R3 후보 감수 시점의 기록이다. 이후 사용자가 1.2.0 릴리즈와 이전 릴리즈와의 A/B 평가를 요청했다. 배포 문서와 릴리즈 노트를 갱신하며, R3 manifest는 감수 당시 패킷의 식별자로 보존한다. 릴리즈 배포 스킬의 본문과 Codex metadata·설치기·테스트는 R3와 동일하다. 새 A/B 평가 자료는 `evaluation/ab-20260930/`에 분리한다.
