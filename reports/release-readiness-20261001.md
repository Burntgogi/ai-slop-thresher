# AI Slop 탈곡기 v1.2.1 릴리즈 준비 검토

후속 상태: 이 문서는 가독성 보완 전 후보의 준비 기록이다. 사용자 반응을 반영한 후속 후보와 문서 A/B/C는 [후속 개선 보고서](abc-readability-20261001.md)에 별도로 기록한다. 아래 ZIP·체크섬과 당시 검사 결과는 가독성 보완 전 후보에 대한 기록으로 유지한다.

2026-10-01. 탈곡기의 v1.2.1 후보를 준비했다. 기존 v1.2.0 공개 배포물과 사용자 설치본은 유지했다. 커밋·푸시·태그·릴리즈 게시·설치는 진행하지 않았다.

## 범위와 변경

이번 세션은 탈곡기의 지침과 검증·패키징에 집중한다. Codex·Dot·Muse 협업 도구의 구현·VM 배치·왕복 시험은 별도 세션으로 인계했다. 인계 위치는 작업 루트의 `SESSION-SPLIT-20261001.md`다. 협업 도구 코드·DB·세션 원응답과 미공개 협업 평가 초안은 후보 ZIP에서 제외했다. 저장소에 이미 공개된 역사 감수 요약은 보존했다.

변경은 사용자가 지정한 두 항목이다.

1. 필요한 정보가 없는 흥미·칭찬 반응을 삭제한다. 반응과 함께 담긴 사실·원인·조건·책임·조치는 남긴다. 서평의 감상과 실제 발화의 인용처럼 표현 자체가 내용이면 보존한다. 기존 부정·대조의 의미 보존 기준과 `ai-slop-thresher`·`thresh` 호출 구조를 유지한다.
2. 재검증과 재빌드를 분리한다. 검사·사례 대조·A/B 재집계는 기본 실행에서 기존 기록을 쓰지 않는다. ZIP 생성은 `--apply`와 소스 밖의 새 출력 폴더를 요구한다. 기존 출력 폴더를 거부하고, 추적된 파일과 명시적으로 포함한 파일만 작업 자료에 넣는다. 기존 ZIP의 체크섬 일치와 현재 소스와의 일치를 따로 판정한다.

| 수정 후 집중 확인 | 새 릴리즈 검사 7개 통과. 읽기 전용 실행 전후의 저장소 파일 보존, 손상 ZIP 거부, 원본 변경과 기존 ZIP 무결성의 구분 등을 확인했다. |
| 플러그인 생성물 | 10개 파일이 정본과 일치하고 상대 참조가 해결됐다. 두 스킬의 형식 검사를 통과했다. |
| 후보 빌드 | 소스 213개 파일을 선택했고, 빌드 전후 저장소 파일 내용이 같았다. ZIP 4종의 체크섬·CRC와 portable/Codex ZIP의 원본 일치 검사가 통과했다. |
| Git 없는 재빌드 | 생성한 작업 자료 ZIP을 임시 폴더에서 풀고 포함 목록으로 재빌드했다. 같은 Windows·Python 환경에서 ZIP 4종의 바이트가 모두 같았다. 다른 OS·VM 재현성은 검사하지 않았다. |
| 기존 기록 | v1.2.0 ZIP 4종의 기록된 체크섬이 일치했다. 과거 5회 개선 기록의 출력 해시를 재확인했다. 과거 A/B 입력·출력·판정을 덮어쓰지 않았다. |
| 사용자 설치본 | 정본 SKILL.md의 버전이 v1.2.0이고 기존 SHA256과 같았다. 후보를 설치하지 않았다. |

검증 과정에서 출력 변수의 이름 충돌로 임시 검사 폴더가 생성되는 문제를 발견했다. 변수를 분리하고 해당 폴더를 제거했으며, 읽기 전용 확인의 파일 비교 범위를 저장소 전체로 넓혔다.

문장 검토는 흥미·칭찬 제거, 20개 제한, 취소 조건, 원인·책임, 미입증과 무효의 구별, 감상과 인용 보존을 포함한 6건을 자체 검토로 기록했다. 새 독립 평가나 삼자 감수는 아니다. 이전 A/B와 사용자 응답인 “차이가 없어 보인다”를 v1.2.1의 성능 증거나 선호 선택으로 바꾸지 않았다.

## 후보와 후속 단계

후보 파일은 `../../release-candidates/ai-slop-thresher-v1.2.1/`의 portable, Codex plugin, 호환 ZIP과 workbench ZIP이다. 이 폴더의 `SHA256SUMS`, `build-report.json`, `readiness-check.json`에 체크섬·포함 목록·최종 확인 결과를 기록했다. 이 보고서는 빌드 후 작성한 로컬 준비 기록으로 후보 ZIP의 포함 목록에는 없다.

후보는 두 개선 항목을 반영한 배포 준비 상태다. 품질 우월성을 주장할 근거는 추가하지 않았다. 후속 배포 때는 새 후보를 재검증하고, 그 후보를 기준으로 커밋·태그·릴리즈·설치를 진행한다. 협업 도구 개선과 중간 이하 우선순위의 추가 작업은 별도 범위로 남긴다.
