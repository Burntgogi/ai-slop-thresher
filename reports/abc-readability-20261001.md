# v1.2.1 가독성 개선과 문서 A/B/C

2026-10-01 KST. 사용자 반응을 반영해 v1.2.1 후보의 쉼표·조사·문장 연결 기준을 보완하고, v1.1.0·v1.2.0·후보를 같은 원문으로 비교했다. 이번 관측에서 후보는 정보 경계를 표시하는 쉼표와 연락 기한·완료 보장의 문장 분리를 유지했다. 전체 버전의 우열은 정하지 않는다. 사용자 선호 평가는 아직 받지 않았다.

## 반영한 변경

절의 경계·대조·의미 구분·정보 전환을 돕는 쉼표는 남긴다. 조사와 연결 표현의 기능을 확인하고 특정 표현을 일괄 추가하지 않는다. 겹친 절·명사화를 줄이거나 주어와 서술어를 맞추기 위해 문장을 나눌 때도 부정·조건·약속의 강도를 유지한다. 정보 없는 흥미·칭찬 제거와 재검증·재빌드 분리는 유지했다.

첨부된 과거 비교는 A=v1.2.0, B=v1.1.0이었다. 댓글 두 건의 B 선호를 새 후보의 사용자 투표로 바꾸지 않았다. 당시 쉼표를 선호했다는 관측만 개선 설계의 근거로 사용했다.

## 실제 실행

가상 도서관 공지 한 편을 고정했다. 각 버전의 편집자를 새 문맥으로 분리해 자신의 지침과 경계 사례, 공통 원문·요청만 읽도록 했다. 이전 두 버전은 Git 태그의 본문을 추출했으며 설치본을 전환하지 않았다. 실행 기록의 입력·출력 해시를 실제 파일과 대조했다. 첫 완성본은 후편집하지 않았다.

최초 R1에서 후보는 “발생할 수 있는 문제”를 “예약 과정의 문제”로 축약했다. 실제 발생을 단정했다고 확정하지는 않지만 가능성 표시가 덜 분명해져 보완 대상으로 판정했다. 명사를 꾸미는 가능성·조건도 보존하도록 지침을 수정한 뒤 R2에서 세 버전을 새 편집자로 한 번씩 더 실행했다. 출력은 총 6개다. R1과 R2의 후보 지침은 달라 같은 고정 후보의 반복 시험으로 합산하지 않는다. [R1 기록](../evaluation/abc-20261001-r1/review.md), [R2 계획](../evaluation/abc-20261001-r2/protocol.md)

문자 수와 쉼표 수는 관측값이며 품질 점수가 아니다. 과거 v1.1.0 출력에는 쉼표가 8개였지만 이번에는 2개다. 같은 버전에서도 결과가 달라지므로 이전 출력의 쉼표 선호를 버전의 고정 성향으로 해석하지 않는다.

원문의 15개 의미 묶음을 제작자가 수동 대조했다. v1.2.0과 후보는 목록의 주장을 보존했다고 판단했다. v1.1.0도 주요 목적·기간·수치·책임·조건·유보·향후 약속을 남겼으나, F01의 “보다 편리하게”에서 비교 정도를 생략한 점을 주의로 기록했다. 이는 독립 언어학자의 감수나 자동 정확도 측정이 아니다. [의미 대조와 근거](../evaluation/abc-20261001-r2/meaning-review.json)

세 출력 모두 “서비스는 신청 후 7일 이내이고/이내이며…”의 문장 구조가 남았다. 취소 시한이라는 뜻은 이어지는 문맥에서 파악할 수 있으나 읽는 과정에서 서비스 기간처럼 잠시 해석할 여지가 있다. 후보가 모든 어색함을 해소했다고 판단하지 않는다.

## 사용자 비교와 릴리즈 상태

R2의 전문을 무작위 순서로 배치한 [버전명 없는 비교문](../evaluation/abc-20261001-r2/comparison-blind.md)을 만들었다. HTML판은 같은 폴더의 comparison-blind.html이다. 원문도 확인할 수 있다. 버전 매핑은 별도 파일에 기록했으며 사용자의 선호/동률과 이유는 pending이다. 과거에 원문과 출력에 노출된 사용자이므로 완전한 블라인드라고 주장하지 않는다.

두 스킬 형식 검사, 플러그인 10파일의 정본 일치 검사를 통과했다. 자동 검사 41개 중 38개 통과, Windows 심볼릭 링크 생성 권한이 필요한 3개는 건너뛰었다. 명사 수식어 지침 보완 후 형식·생성물 일치 검사를 다시 확인했다. 검사 코드에는 이번 문장 개선으로 인한 변경이 없다.

후속 후보 ZIP은 기존 후보와 다른 새 출력 폴더 ../../release-candidates/ai-slop-thresher-v1.2.1-abc-r2에 만든다. 해당 폴더의 SHA256SUMS·build-report.json·readiness-check.json이 생성·최종 검사의 근거다. 기존 공개 ZIP·과거 평가·설치본 보존은 R1의 preservation-before.json과 대조한다. 이 보존 목록의 로컬 절대 경로와 pending 사용자 평가 상태는 배포 작업 자료에 포함하지 않는다.

이번 입력은 지침 설계자가 이미 읽은 공지문이며 미노출 자료의 일반화 시험이 아니다. 런타임 모델 ID·temperature·seed는 노출되지 않는다. 새 문맥 생성자는 VM으로 파일 접근을 격리한 실행이 아니다. 내용 없는 흥미·칭찬이 원문에 없어 제거 기능은 이 비교로 판정하지 않는다. Dot·Muse 발송, 협업 도구 변경, 설치·커밋·태그·릴리즈 게시는 수행하지 않았다.
