# v1.1.0 / v1.2.0 릴리즈 A/B 평가 사전 계획

2026-09-30. 출력 생성 전에 입력·판정 기준을 고정한다. v1.1.0과 v1.2.0의 실제 GitHub 릴리즈 ZIP을 다운로드해 공개 asset digest와 대조한다. 각 ZIP의 본 스킬과 edge-cases 참고 문서를 평가 instruction으로 사용한다. 설치 경로나 플러그인 UI의 자동 선택 성능은 이 실험의 대상이 아니다.

## 입력과 반복

이전 개선에 사용한 16건과 경계 2건, 그 개선에 사용하지 않은 새 합성 사례 10건을 구분해 총 28건으로 평가한다. 새 10건은 개발 회차에 대해 보류한 사례일 뿐 독립 외부 코퍼스가 아니다. 같은 입력·요청과 같은 Codex 하네스 설정을 두 버전에 적용한다. 버전마다 두 번 생성하고 매 arm/repetition은 새 에이전트 문맥을 사용한다. 한 문맥 내에는 28개 사례가 함께 들어가므로 케이스 간 맥락은 완전히 분리되지 않는다. 순서는 기록한다.

생성자는 자신의 한 릴리즈 스킬, edge-cases, 입력만 읽는다. 다른 arm의 출력·사전 의미 판정·예상 답안은 제공하지 않는다. 생성 결과는 고치지 않고 JSON 문자열로 보존한다. 생성자를 바꾸지 않고 retry해 결과를 골라 쓰지 않는다. 누락이나 잘못된 JSON은 형식 보정 요청과 전후 원문을 기록한다.

## 버전을 숨긴 판정

각 입력·반복 쌍의 출력은 난수로 왼쪽·오른쪽을 배치한다. 새 판정 에이전트에게 source/request와 출력 쌍, 다음 기준을 제공하며 버전명·생성자 ID·개발 결론·arm 매핑은 제공하지 않는다. 판정자는 왼쪽/오른쪽만 선택하고 구체적 원문과 출력 구간을 근거로 적는다. 생성 에이전트와 판정 에이전트는 분리한다. 주 에이전트는 모든 판정을 받은 뒤 버전 매핑을 해제한다. 출력만으로 버전을 추측할 가능성은 있으며 블라인드 성공 자체를 증명하지 않는다.

1. 의미 보존: 행위자·사실·수치·시점·인과·명제 강도·부정·정정·책임·피해·조건·배타 범위·의무·불확실성·저자 평가·직접 인용을 보존했는가. 새로운 사실이나 원문에 없는 안심을 추가하면 실패다. 반복 수사만 덜어내는 것은 의미 실패로 보지 않는다. 모호한 고유 명제를 삭제하면 실패다.
2. 요청 준수: 본문만/진단만/비교, 말투, Markdown 번호와 코드 등 지정 형식을 지켰는가.
3. 스타일: 의미와 요청을 둘 다 보존한 출력끼리만 자연스러움과 불필요한 부정·재정의/문제 축소 수사 제거를 비교한다. 개선이 없으면 동률이다. 원문이 이미 적절해 동일하게 유지한 것은 실패가 아니다. 단어·문구 빈도만으로 우열을 판정하지 않는다.

각 출력에 semantic_pass, request_pass, 실제 문제/근거를 기록하고 쌍에는 style_winner(left/right/tie/not_comparable)와 이유를 기록한다. 집계는 arm별 보존 통과 수와 요청 통과 수, 비교 가능한 쌍의 승/패/동률, 개발 사례와 새 사례를 각각 표시한다. 두 반복은 동일 사례의 의존 관측이므로 독립 표본 수나 유의성으로 표현하지 않는다. 문장 길이 단축률·AI 탐지 성능·객관적 사람다움 점수는 측정하지 않는다.

## 재현성과 한계

asset SHA-256, member SHA-256, 입력·출력·판정 SHA-256, 릴리즈 태그/커밋, agent ID, 실행 순서와 완료 시각을 기록한다. 에이전트가 실제 모델 식별자·temperature·seed를 제공받지 못하면 unknown/inherited로 남기며 추정하지 않는다. 같은 Codex 모델 계열·공통 시스템/개발자 문체 지침을 사용하는 탐색적 비교다. 공통 문체 지침이 양 arm의 동작에 영향을 줄 수 있다. 사람 평가, 다른 기반 모델, 제품별 실제 설치 테스트나 일반화 성능은 입증하지 않는다. 성능이 비슷하거나 이전 버전이 더 좋으면 그대로 보고한다.

릴리즈 소스를 이 평가 결과로 바꾸면 비교 대상을 새로 고정하고 다시 실행해야 한다. 이번 평가 중에는 스킬 지침을 변경하지 않는다. 사후 발견은 공개 릴리즈와 분리한 후속 과제로 기록한다.
