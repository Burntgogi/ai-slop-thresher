# 2026-09-30 후보 개선 기록

기준 저장소 커밋은 `1ce5dddaff01c4353a71bbaf2abcb03f66dd4965`다. 기존 `evaluation/rounds/`, `versions/`, `checks/`, `semantic-review.json`은 이전 제작의 역사 자료다. 이 디렉터리는 1.2.0 미공개 후보의 별도 기록이다.

초기 구현 뒤 다섯 번 관측·검토·수정을 연결한다. 회차 1~3은 문체·의미·선택 설명, 회차 4~5는 설치·배포·검증의 오류를 함께 다룬다. 매 회차 스킬 입력 스냅샷을 남기고 동일 원문 16건을 별도 Codex 에이전트에 다시 적용시킨다. 이후 출력과 검토를 보존하고 다음 수정에 연결한다. 회차 3에는 제한·책임에 관한 추가 입력 2건을 실행한다. 원출력을 편집하거나 실패한 출력을 성공한 것으로 덮어쓰지 않는다.

입력 작성·의미 평가·지침 수정은 주 Codex가 담당하고 출력 생성은 기대 답안을 받지 않은 `forward_eval` 에이전트가 담당한다. 에이전트는 공통 지침·필요한 참고 문서·입력만 읽도록 요청받았다. 각 케이스는 최초 원문에서 시작하되 같은 에이전트와 대화에서 재실행한다. 따라서 이전 작업의 맥락을 완전히 제거한 블라인드 평가가 아니다. 여러 케이스를 같은 호출에서 처리하므로 케이스 간 컨텍스트 영향도 통제하지 않았다. 합성 사례이며 사람 평가, 별도 모델 비교, 기존 버전과의 paired 실행, 홀드아웃 성능 검증은 수행하지 않았다.

모델 설정은 부모 에이전트의 상속값이다. 도구 반환에서 구체적인 모델 ID와 샘플링 설정을 확인할 수 없어 임의로 기입하지 않았다. 파일 기록 시각은 UTC다. `captured_at`은 증거 파일을 만든 시각이며 개별 모델 호출 시작·종료 시각이 아니다. 회차 1의 스냅샷은 출력 회수 후 첫 수정 전에 저장했다. 그 사이 지침과 입력을 변경하지 않았다.

`review.json`의 사례 판정은 주 Codex가 직접 원문과 출력의 명제, 수치의 귀속, 부정·조건·의무, 저자의 평가, 인용과 요청 모드를 읽어 비교한 기록이다. 자동 점수나 객관적인 자연스러움 판정으로 해석하지 않는다. 회차 4~5의 동작 검사는 임시 디렉터리를 사용하며 실제 사용자 하네스에 설치하지 않는다.

```sh
python evaluation/improvement-20260930/record.py verify
```

이 명령은 입력 스냅샷의 해시, 원출력과 검토의 연결, 16건의 중복·누락, 다섯 회차의 기록 완결성을 확인한다. 새로운 윤문이나 의미 평가를 생성하지 않는다. Dot·Muse는 클라우드 채널에서 따로 탐색·감수한다. 각자의 실제 응답, 제공받은 후보의 범위와 검토 한계를 보고서에 구별한다.
