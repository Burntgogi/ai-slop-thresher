## 실행 순서

1. **지침을 한 번 보완하고 고정한다.** 최근 피드백의 핵심인 의미 보존형 압축과 정보 위치의 판단 기준을 기존 작업·편집 기준에 통합한다. 반복 지칭과 긴 구문부터 줄이고, 조사·접속 표현은 삭제해도 관계와 범위가 명확할 때만 덜어낸다. 같은 역할의 정보가 흩어지거나 필요한 전제가 늦게 나올 때만 묶음과 위치를 조정한다. 이동 후 조건·예외의 적용 대상, 지시어의 선행 대상과 인과·대조·시간 관계를 다시 확인한다. 기존 전개가 적절하거나 재배열의 이유가 불확실하면 유지한다. 공지·논증·서사 모두에 기승전결이나 동일한 문단 틀을 강제하지 않는다. 기존 지침과 중복되는 문장은 정리하고 경계 사례는 실제 판단에 도움이 되는 소수만 보완한다.

2. **비교 실험을 종료하고 한 차례 회귀 확인한다.** 새 A/B/C 실행이나 추가 사람 투표를 요구하지 않는다. 이미 있는 사례에서 빈 칭찬과 필요한 사실의 구별, 부정·책임, 취소의 두 조건, 가능성·한도·단위와 기능 있는 연결을 집중 확인한다. 최신 공지의 원문·출력·의미 목록을 사용해 재배열로 조건이나 선행 대상이 흐려지지 않는지 검토한다. 수동 보완 예시는 확인용 자료로 구분하고 독립 실행·성능 점수로 집계하지 않는다. 최종 확인에서 실제 결함이 나오면 해당 부분을 고치고 영향받은 항목만 다시 확인한다. 모든 판정 항목을 새 대규모 평가로 확장하지 않는다.

3. **현재 배포 문서와 생성물을 맞춘다.** README, 현재 릴리즈 노트, CHANGELOG와 설치·검증 안내를 실제 확정 버전에 맞춘다. 최신 X=v1.2.1 후보 선호는 두 번째 문단 보완 의견을 포함한 직접 응답 1건으로 설명한다. 예전 C=v1.2.0 선호와 합산하거나 전체 성능 우월성으로 해석하지 않는다. 이전 보고서·실험·패키지의 pending 표시는 해당 시점의 기록으로 보존하고 최신 안내에서 회수된 상태를 설명한다. ai-slop-thresher를 정본, thresh를 별칭으로 유지하고 공통 스킬과 Codex 생성물의 참조·버전을 일치시킨다. 협업 도구와 VM 개발은 별도 범위로 유지한다.

4. **최종 후보를 한 번 빌드하고 검증한다.** 이미 변경된 검사·설치·패키징 코드의 기존 테스트를 최종 소스에서 한 번 실행하고 Windows 권한 등에 따른 건너뜀은 구분해 기록한다. 두 스킬의 형식, 플러그인 정본 일치, 상대 참조와 공백 오류를 검사한다. 소스 밖의 새 폴더에 portable, Codex plugin, 호환 이름, workbench ZIP과 SHA256SUMS를 생성한다. 체크섬·CRC·원본 바이트 일치와 작업 자료의 포함 목록을 대조하고 빌드 전후 소스가 같은지 확인한다. 과거 ZIP·실험·C: 체크아웃·설치본은 후보 제작 단계에서 보존한다. 불필요한 비교 도구·VM 파일·로컬 경로 목록·임시 자료를 새 작업 자료에 추가하지 않는다. 패키징 코드가 바뀌지 않으면 이미 수행한 Git 없는 재빌드 시험과 다른 OS 시험을 반복하지 않는다.

5. **확정본으로 배포와 설치를 마무리한다.** 실행 단계에서는 변경 요약·검증 결과·알려진 한계를 정리하고 탈곡기 범위의 변경만 커밋한다. 버전 태그와 GitHub 릴리즈는 같은 확정 소스에서 만든 ZIP을 사용한다. 설치는 공개한 배포물의 해시를 확인한 후 기존 사용 경로와 중복 설치 여부를 점검하고 백업·복구 방법을 확보해 갱신한다. 설치 파일의 버전·참조를 확인하고 핵심 호출을 한 번 점검한다. 디스크상의 설치 확인과 현재 세션에서 새 지침을 읽었는지는 구분해 보고한다. 오늘의 계획 수립 자체로 배포나 설치가 실행된 것으로 취급하지 않는다.

## 완료 기준

지침·별칭·플러그인·문서·ZIP·태그·설치본의 버전과 내용이 일치하고, 최종 회귀 확인에서 의미 손실이 발견되지 않으며, 기존 기록이 보존되면 마무리한다. 품질 우월성이나 추가 표 확보를 완료 조건으로 삼지 않는다. 최종 보고에는 무엇이 바뀌었는지, 실제 확인한 범위, 건너뛴 검사와 복구 위치를 간단히 남긴다.

이번 계획의 변경 범위는 탈곡기 지침·경계 사례·배포 문서·생성물과 기존 검증 절차의 실행이다. 테스트가 실제 결함을 찾았을 때 필요한 수정을 제외하면 설치 구조·호출 체계·협업 도구·비교 UI의 추가 개발을 포함하지 않는다.
