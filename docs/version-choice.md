# 같은 글로 두 버전을 써 보고 선택하기

v1.2.0을 기본 배포로 유지합니다. 공통 스킬과 Codex 플러그인을 분리하고 필요한 부정과 반복 수사를 구별하도록 개선했습니다. 평가에서 모든 글의 문체가 이전보다 좋아졌다는 결론은 얻지 못했습니다. 이미 v1.1.0에 만족한다면 그대로 사용할 수 있습니다. 자신의 글에서 더 만족스러운 버전을 선택하세요.

## 먼저 읽어 볼 결과

[추가 문서 비교와 최종 검토](../reports/final-review-20261001.md)에 새 공지 한 편의 원문과 두 수정문 전문을 실었습니다. 이 문서에서 의미와 요청은 양쪽 모두 최종 판정을 통과했습니다. Codex·Muse는 v1.1.0의 가벼운 문체를, Dot은 v1.2.0의 기한 설명을 근소하게 선호했습니다. 같은 한 문서의 판단을 성능 승률로 집계하지 않습니다.

사람 평가는 아직 수행하지 않았습니다. [버전 표시를 숨긴 비교 페이지](compare-versions.html)를 브라우저에서 열면 원문과 두 수정문을 읽고 선택한 뒤 버전을 확인할 수 있습니다. 페이지의 평가 입력은 설치를 바꾸거나 저장소에 전송하지 않습니다. 이미 버전별 결과를 본 사람에게는 완전한 블라인드 시험이 아닙니다.

## 자신의 글로 비교하기

평소 다듬는 글을 같은 원문으로 저장합니다. 두 버전에 동일한 요청을 주고 최초 수정문을 비교하세요. 예를 들면 다음과 같습니다.

```text
아래 원문을 정중한 말투로 자연스럽게 다듬어 주세요.
사실, 수치, 조건, 책임, 불확실성, 향후 조치와 약속을 보존하세요.
제목과 문단 형식은 유지하고 수정한 본문만 주세요.
```

가능하면 같은 모델 설정의 새 대화에서 버전별로 실행합니다. 한쪽 결과나 이전 판정은 다른 실행에 주지 않습니다. 새 대화만으로 모델의 공통 지침과 기존 기억까지 완전히 격리되는 것은 아닙니다.

| 먼저 확인할 것 | 비교할 질문 |
| --- | --- |
| 의미 | 수치·조건·책임·유보·향후 약속이 남았는가? |
| 요청 | 말투·제목·문단·출력 범위를 지켰는가? |
| 문체 | 자신의 독자가 읽기 편한가? 반복이 줄고 연결이 자연스러운가? |
| 실사용 | 선택한 하네스에서 설치·호출하기 편한가? |

의미나 요청을 어긴 결과는 먼저 탈락시킵니다. 둘 다 만족하면 문체와 사용 경험으로 고르세요. 차이가 작으면 한 번의 결과로 단정하지 않고 다른 글에서도 비교할 수 있습니다. 더 짧다는 이유만으로 더 좋은 윤문이라고 판단하지 않습니다.

## 버전을 구별해서 실행하기

[v1.1.0 릴리즈](https://github.com/Burntgogi/ai-slop-thresher/releases/tag/v1.1.0)와 [v1.2.0 릴리즈](https://github.com/Burntgogi/ai-slop-thresher/releases/tag/v1.2.0)를 서로 다른 폴더에 풉니다. 비교할 때는 한 실행에 한 버전의 `ai-slop-thresher/SKILL.md`와 필요한 참조 문서만 명시적으로 읽게 합니다. 실제 읽은 버전과 파일을 기록하세요. 이미 같은 이름으로 설치된 다른 버전을 자동으로 선택하면 비교가 섞일 수 있습니다.

두 버전을 같은 스킬 디렉터리에 동시에 설치하지 않습니다. Codex에서는 플러그인과 직접 스킬 설치 중 한 방식을 고릅니다. v1.1.0은 이전 스킬 포장이고, 분리된 Codex 플러그인 포장은 v1.2.0의 기능입니다. 플러그인 UI 설치 경험과 윤문 결과 비교를 구별하세요.

## 선택 후 설치

- v1.2.0이 더 좋으면 [하네스별 설치 안내](installation.md)에 따라 설치하거나 현재 설치를 유지합니다.
- v1.1.0이 더 좋으면 현재 설치를 백업하고 [이전 릴리즈 안내](releases/v1.1.0.md)에 따라 전환합니다. 새 설치를 덮어쓰거나 백업을 지우지 않습니다.
- 아직 결정하지 않았다면 현재 설치를 유지하면서 별도 폴더에서 비교합니다.

직접 설치 스크립트는 기존 같은 이름의 스킬을 덮어쓰지 않습니다. 플러그인 사용자는 해당 제품의 설치·제거 경로를 따르고 이전 직접 스킬을 중복 등록하지 않아야 합니다. 로컬 선택은 원격 Dot·Muse VM의 버전을 자동으로 바꾸지 않습니다. 원격 실행마다 실제 읽은 지침 버전을 확인해야 합니다.

피드백을 남길 때는 선택한 버전, 하네스, 모델 설정을 아는 범위, 원문과 최초 수정문, 좋아진 점이나 사라진 의미를 적어 주세요. 개인정보가 있는 원문을 공개할 필요는 없습니다. 작업자의 운영 권고가 사용자의 문체 취향을 대신하지 않습니다.
